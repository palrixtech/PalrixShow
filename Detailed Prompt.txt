## IMPORTANT

I have an existing project that was built for a product catalog/showcase concept.

I will provide that existing project/codebase to you.

Use the existing project as a **reference and source of existing data/content**, but redesign the UI/UX according to this prompt.

### Reuse from the existing project where appropriate:

* Seller/business information
* Product information
* Product images
* Existing product data
* Existing story/content/data
* Existing assets
* Existing routing structure if useful

### Do NOT preserve the existing UI just because it already exists.

The UI/UX needs to be redesigned from the ground up around the requirements below.

---

# 1. WHAT THIS PRODUCT IS

This is NOT an Amazon-like or Flipkart-like e-commerce website.

It is NOT a traditional product catalog with product cards, grids, filters, product-detail pages, cart, and checkout.

The product should feel closer to:

* Instagram Reels
* TikTok
* YouTube Shorts

but specifically designed for **showcasing products**.

The simplest way to understand the product is:

> **One seller. One URL. Products displayed as a vertical Reels-style feed.**

A seller gets one URL, for example:

```text
https://example.com/raj-fashion
```

When a customer opens this URL, they should immediately see the seller's products in a **full-screen vertical scrolling experience**.

The customer can:

* Scroll/swipe to the next product
* Like a product
* Share a product
* Contact the seller about that specific product through WhatsApp

The main objective is to help sellers stop sending dozens of product photos/videos individually through WhatsApp or continuously posting products on WhatsApp Status.

Instead, they can simply share one link.

Example:

> New collection is here 👗
> Check all products:
> https://example.com/raj-fashion

They should feel like they are discovering products through a social-media-style feed.

# 4. PRODUCT IS A MEDIA ITEM

This is extremely important.

A product is NOT limited to an image.

A product can contain:

* One image
* Multiple images
* One video
* Multiple videos
* A combination of images and videos

Examples:

### Product with one image

```text
Product A
└── image.jpg
```

### Product with one video

```text
Product B
└── video.mp4
```

### Product with multiple images

```text
Product C
├── image-1.jpg
├── image-2.jpg
└── image-3.jpg
```

### Product with mixed media

```text
Product D
├── video.mp4
├── image-1.jpg
└── image-2.jpg
```

The UI must support all of these.

Do NOT design the application assuming every product has only one image.

Think of every product as:

> **A product + a collection of media items.**

---

# 5. TWO TYPES OF SWIPING

There are two different navigation directions.

## Vertical swipe = NEXT PRODUCT

This is the primary interaction.

Example:

```text
Product 1
    ↓ swipe up
Product 2
    ↓ swipe up
Product 3
    ↓ swipe up
Product 4
```

Each product should occupy approximately the entire viewport.

---

## Horizontal swipe = MEDIA WITHIN CURRENT PRODUCT

If a product has multiple media items, the customer can move between them horizontally.

Example:

```text
Product 1

Image 1  →  Image 2  →  Video
```

Vertical swipe then moves to the next product.

This distinction is important:

> **Vertical = product navigation**

> **Horizontal = media navigation inside the current product**

If implementing horizontal swipe creates conflicts with vertical scrolling or poor mobile usability, provide a tap-based media navigation fallback.

---

# 6. FULL-SCREEN REELS-STYLE LAYOUT

The main product feed should occupy the viewport.

Each product should approximately use:

```text
100dvh
```

Use viewport-aware responsive sizing.

The main feed should use vertical snapping.

Conceptually:

```css
scroll-snap-type: y mandatory;
```

and each product:

```css
scroll-snap-align: start;
```

The user should naturally stop at one product at a time.

The experience should feel smooth and intentional.

---

# 7. PRODUCT MEDIA IS THE HERO

The media should dominate the screen.

The product image/video should receive approximately **80–90% of the user's visual attention**.

Do NOT place the product inside a traditional white card.

Avoid this:

```text
┌──────────────────────┐
│ Product Image        │
│                      │
├──────────────────────┤
│ Product Name         │
│ Price                │
│ Description          │
│ Add to Cart          │
└──────────────────────┘
```

Instead, use a full-screen visual experience:

```text
┌─────────────────────────┐
│                         │
│                         │
│       PRODUCT           │
│       IMAGE / VIDEO     │
│                         │
│                         │
│                         │
│ Product Name       ♡   │
│ ₹899                ↗   │
│ Description         🟢  │
└─────────────────────────┘
```

Product information should be overlaid on top of the media using gradients where necessary.

---

# 8. IMAGE PRODUCTS

For image-based products:

* Show the image prominently
* Preserve the image's aspect ratio
* Never stretch or distort the image
* Support portrait images
* Support square images
* Support landscape images
* Use appropriate `object-fit`
* Use a visually pleasing background when the image does not fill the screen

If the product image is portrait, it should feel natural on a mobile screen.

If the image doesn't fill the entire screen, use a subtle blurred/background treatment rather than leaving an ugly empty area.

---

# 9. VIDEO PRODUCTS

Videos should behave like Reels/Shorts.

For a product with video:

* Autoplay when the product becomes active/visible
* Start muted by default
* Loop automatically
* Pause when the product leaves the viewport
* Do not display a traditional large video player
* Do not show unnecessary video controls
* Preserve aspect ratio
* Support portrait videos
* Handle landscape videos gracefully
* Show a mute/unmute control
* Show a poster/thumbnail while the video is loading

Example:

```text
┌─────────────────────────┐
│                         │
│                         │
│       AUTOPLAY          │
│       PRODUCT VIDEO     │
│                         │
│                         │
│                    🔇   │
│                         │
│ Product Name        ♡  │
│ ₹1,499              ↗  │
│                     🟢 │
└─────────────────────────┘
```

The video should feel like a Reel, not like an embedded YouTube player.

---

# 10. VIDEO PERFORMANCE

Because products may contain videos, performance is extremely important.

Do NOT load every video at once.

Implement sensible media loading behavior:

* Load the current product's video
* Preload the next product when practical
* Pause videos that leave the viewport
* Avoid downloading unnecessary videos
* Use poster images where possible
* Optimize loading
* Respect browser autoplay restrictions
* Keep videos muted initially
* Allow the user to unmute
* Avoid memory-heavy behavior when many products exist

Use `IntersectionObserver` or an equivalent approach if appropriate.

The feed must remain smooth on mobile devices.
